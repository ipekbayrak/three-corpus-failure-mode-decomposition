# AGENTS.md

## Repo Purpose
This repo supports a lean, reproducible IDS transfer paper centered on novelty-structured transfer failure in shared-feature tabular settings. The primary goal is to de-risk the science first; the fallback is an honest strong-Q2 empirical paper if the no-target-label proxy fails.

## Pilot-First Rule
Do not build broad infrastructure before the fast-fail pilot is complete. The first question is whether the core empirical relationship is real, not whether the repo is feature-complete.

## Durable Repo Rules

### Core Story
- Primary story: cross-domain IoT IDS transfer under frozen source-side thresholding.
- Center claim: oracle novelty explains degradation; deployable novelty proxy may predict unsafe transfer without target labels.
- Calibration is not a paper theme.
- Theorem 2 is the center of the paper.
- Theorem 3 stays only if empirically non-vacuous and operationally useful.

### Oracle vs Deployable
- Oracle analyses may use target labels.
- Deployable analyses may not use target labels at transfer time.
- Every result must say whether it is oracle-only or deployable.
- Never blur oracle `alpha` with deployable `alpha_hat`.

### Alpha_Hat Freeze Rule
- The default deployable estimator is frozen after the pilot:
  - source IDS thresholded at source-validation `1%` FPR,
  - source-attack-bank `k`-NN outlier rate on target predicted attacks,
  - zero-positive fallback via top-`K` source-score instances.
- No estimator shopping after the pilot freeze.
- Secondary diagnostics are baselines, not replacements.

### Theorem Demotion Rule
- If Theorem 3 is loose, decorative, redundant, or operationally useless, move it to the appendix or drop it.
- Never keep a theorem in the main text just because it existed in a prior draft.

### Claim Narrowing Rule
- Do not claim universality.
- Do not generalize beyond shared-feature tabular IDS transfer.
- Do not claim target-free safety unless the decision task supports it.
- Do not describe `UNSW-NB15` as a semantic peer of the IoT datasets.

### Reproducibility Rules
- No manual tables.
- No prose-only numbers.
- All figures and tables are generated by scripts.
- All runs produce config hashes and manifests.
- Splits, ontology, feature schema, and thresholds are versioned.
- Thresholds are chosen on source validation only.
- No target retuning.

### Leakage Rules
- No target labels for thresholding.
- No target labels for deployable model selection.
- Use capture or session-aware grouping where applicable.
- Use deterministic seeds and manifests.
- Leakage validation scripts are mandatory.

### Minimal Dependency Rule
- Prefer Python + pandas + numpy + scikit-learn + matplotlib + PyYAML.
- Avoid extra libraries unless they remove real work.
- No notebooks as the main execution path.
- No giant sweeps.
- No custom deep sequence models.
- No over-engineered framework code.

### Canonical Commands
- `make env`
- `make pilot`
- `make features`
- `make benchmark`
- `make decision`
- `make render`
- `make validate`
- `make test`

### What Counts as Done
- Pilot checkpoint complete.
- Hero figure stable.
- Decision task complete.
- Provenance checks pass.
- Theorem 3 is either justified or cut.
- Manuscript numbers trace back to artifacts.

### Do-Not-Do List
- Do not overbuild the repo before the pilot.
- Do not add calibration as a paper theme.
- Do not create per-dataset feature schemas.
- Do not add more models unless one of the required models fails technically.
- Do not keep decorative theory.
- Do not use cross-domain paired significance tests on unmatched units.
- Do not hand-edit tables or figure numbers.
- Do not widen claims into a general transfer law.
